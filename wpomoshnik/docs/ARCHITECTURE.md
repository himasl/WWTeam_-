# Архитектура WПомощника

## Схема MVP

```
Планшет сотрудника (браузер)
  экран встречи: вопрос голосом или текстом, ответ, подсказки, чек-лист
  экран аналитики: частые вопросы и пробелы базы знаний
        |  HTTP, JSON
        v
API (FastAPI, app/main.py)
  POST /api/ask        вопрос -> ответ, источник, подсказки
  POST /api/escalate   передать вопрос без ответа в поддержку
  GET  /api/stats      данные для аналитики
        |
        +--> Поиск (app/kb.py)       BM25 по разделам базы знаний, русская морфология
        |       |                    проверка уверенности: мало совпадений -> «нет ответа»
        |       v
        |    База знаний (kb/*.md)   раздел = несколько коротких фактов, источник, дата
        |
        +--> Модель (app/llm.py)     Ollama: формулирует ответ только по найденным разделам
        |                            модель недоступна -> ответ цитатой из раздела
        |
        +--> Журнал (app/db.py)      SQLite: вопрос, найден ли ответ, тема, время, эскалация
```

## Как проходит вопрос

1. Сотрудник выбирает продукт встречи и задаёт вопрос. Голос превращается в текст в браузере.
2. Поиск находит три самых подходящих раздела базы знаний. Разделы выбранного продукта получают двойной вес.
3. Проверка уверенности: если важные слова вопроса не встречаются в лучшем разделе, помощник отвечает «нет ответа» и модель не вызывается. Так модель не может выдумать цифру.
4. Модель получает вопрос и три раздела, возвращает JSON: ответ в два-три предложения, номер раздела-источника, что уточнить, что предложить. Модель тоже может вернуть «нет ответа».
5. Планшет показывает ответ крупно, под ним источник, дату данных и ссылку.
6. Вопрос записывается в журнал. Вопросы без ответа попадают в «Пробелы в базе знаний».

## Решения и причины

| Решение | Причина |
|---|---|
| Сначала поиск, потом модель | Ответ всегда привязан к документу, на планшете видно, откуда цифра |
| Отказ решает поиск, а не только модель | Модель не видит вопросов, на которые нет материала |
| BM25 без векторной базы | Запускается одной командой, не нужен GPU; векторы добавляются позже рядом |
| Провайдер модели в настройках | Смена на российскую или локальную модель без правок кода |
| База знаний в markdown | Легко править и проверять глазами, у каждого факта есть источник |
| В запросе нет данных клиента | Вопрос касается продукта, а не человека; проще требования 152-ФЗ |

## Ограничения MVP

- База знаний собрана из открытых обзоров, внутренних регламентов банка в ней нет.
- Длинные разговорные вопросы поиск часто отклоняет как «нет ответа».
- Голосовой ввод работает через браузер и требует интернета.
- Нет входа по учётной записи, журнал общий для всех.

## Целевая архитектура для пилота в банке

| Часть | MVP | Пилот |
|---|---|---|
| Модель | Ollama | Российская или локальная модель в контуре банка |
| Поиск | BM25 | BM25 и векторный поиск вместе |
| База знаний | Файлы из открытых источников | Выгрузка из базы знаний и тарифов банка с обновлением |
| Голос | Распознавание в браузере | Распознавание речи в контуре банка |
| Журнал | SQLite | PostgreSQL, роли сотрудника и руководителя |
| Вход | Нет | Корпоративная учётная запись |
| Размещение | Один процесс | Контейнеры в закрытом контуре без доступа в интернет |
